# Инструкция самонастройки агента на DeepSeek

**Для кого:** агент, работающий через DeepSeek API, обслуживающий навыки Салавата:
ответы клиентам, документы/КП, заявки → CRM, Telegram-бот сотрудников (расчёт по прайсу),
автозаполнение Excel-описаний товаров.

**Агенту:** прочитай целиком, выполни раздел 9 (чек-лист самонастройки), затем раздел 10 (тесты).
Данные проверены по состоянию на **31.07.2026**. Всё, что не удалось проверить, помечено 【так】.

---

## 1. Модели — КРИТИЧНО, июль 2026

Старые ID **`deepseek-chat` и `deepseek-reasoner` ОТКЛЮЧЕНЫ 24.07.2026**. Если ты
сконфигурирован на них — запросы будут падать. Замени на:

| Модель | Что это | Когда использовать |
|---|---|---|
| `deepseek-v4-flash` | 284B MoE (13B активных), быстрая | 90% задач: клиентские ответы, CRM-парсинг, Telegram-бот, описания товаров |
| `deepseek-v4-pro` | 1.6T MoE (49B активных), умная | сложные: планы внедрения, анализ, многошаговые рассуждения |

- Базовый URL (OpenAI-совместимый): `https://api.deepseek.com`
- Anthropic-совместимый эндпоинт: `https://api.deepseek.com/anthropic` (если твой фреймворк говорит на протоколе Anthropic — например, Claude Code / @ai-sdk/anthropic)
- Контекст: **1M токенов**, максимальный вывод: **384K токенов** — у обеих моделей
- Соответствие старым: `deepseek-chat` ≈ v4-flash без thinking; `deepseek-reasoner` ≈ v4-flash с thinking

Цены (за 1M токенов, проверено 25.07.2026): flash — $0.14 вход / $0.0028 кэш-хит / $0.28 выход;
pro — $0.435 / $0.003625 / $0.87. Кэш-хит в ~50 раз дешевле входа — см. раздел 5.
【Скидки off-peak в V4 не подтверждены — не закладывайся на них】

## 2. Thinking mode — главный источник ошибок

**По умолчанию у V4 thinking ВКЛЮЧЁН** (модель сначала рассуждает, потом отвечает).

Выключение (OpenAI SDK):
```python
response = client.chat.completions.create(
    model="deepseek-v4-flash",
    messages=[...],
    extra_body={"thinking": {"type": "disabled"}},
)
```

Правила:
1. **В thinking-режиме sampling-параметры игнорируются**: `temperature`, `top_p`,
   `presence_penalty`, `frequency_penalty` не работают (ошибки нет — просто нет эффекта).
   Не пытайся управлять стилем через температуру при включённом thinking.
2. **reasoning_content — обязательное состояние в multi-turn с инструментами.**
   Ответ приходит с двумя полями: `reasoning_content` (рассуждение) и `content` (ответ).
   Как только в диалоге появился tool call, каждое assistant-сообщение в истории
   ОБЯЗАНО нести своё `reasoning_content` при отправке обратно — иначе **400**
   («reasoning_content in thinking mode must be passed back»). Сохраняй его в истории as-is.
3. Бюджет рассуждений ограничивай через `max_tokens` (покрывает рассуждение + ответ).
   Задавай `max_tokens` явно всегда.
4. Уровень усилий: поле `reasoning_effort` (OpenAI-формат) / `thinking.budgetTokens`
   (Anthropic-формат). 【Точные допустимые значения effort сверь ответом API — доки закрыты от ботов】

**Когда thinking выключать:** быстрые клиентские ответы, извлечение полей заявки,
расчёт по прайсу через инструмент, генерация описаний товаров — всё, где важны скорость,
цена и управляемая температура.
**Когда включать:** разбор сложной заявки, планирование, нестандартный вопрос клиента.

## 3. Инструменты (function calling) — известный баг

**`tool_choice` принимает только `"auto"`, `"none"` или отсутствие поля.**
`tool_choice="required"` и `tool_choice={"type":"function","function":{"name":...}}`
возвращают **400** «Thinking mode does not support this tool_choice» — на обеих V4-моделях.
Это ломает structured-output в LangChain/CrewAI и подобных (они шлют конкретную функцию).

Что делать:
- всегда `tool_choice="auto"` + жёсткая инструкция в системном промпте: «для расчёта цены
  ВСЕГДА вызывай инструмент get_price, никогда не считай сам»;
- валидируй: если модель ответила текстом там, где ждал tool call, — повтори запрос
  с напоминанием (1–2 ретрая). Без этого ~40% запросов могут уходить в текст;
- для строгих структур надёжнее **JSON mode без инструментов**:
  `response_format={"type":"json_object"}` + слово «json» и пример схемы прямо в промпте +
  валидация ответа по схеме с ретраем при несоответствии.

## 4. Температура (только при выключенном thinking)

| Задача | temperature |
|---|---|
| Код, математика, расчёты, извлечение полей | **0.0** |
| Анализ данных, отчёты | **1.0** |
| Диалог с клиентом, письма, КП | **1.3** |
| Креатив: описания товаров, посты | **1.5** |

Расчёты по прайсу — не доверяй арифметику модели вообще: цифры считает инструмент
(get_price), модель только формулирует ответ.

## 5. Кэш = деньги: структура промпта

Кэширование префикса автоматическое, настраивать нечего, но экономит в ~50 раз только
если начало промпта байт-в-байт стабильно:

```
[СИСТЕМНЫЙ ПРОМПТ — никогда не меняется]      ← кэшируется
[База знаний / прайс / примеры — меняется редко] ← кэшируется
[История диалога]                              ← частично
[Текущий вопрос]                               ← всегда новый
```

Не вставляй в начало промпта время, имя пользователя, случайные ID — это убивает кэш.
Всё динамическое — в конец.

## 6. Русский язык

- В системный промпт первой строкой: **«Отвечай только на русском языке»**. В thinking-режиме
  рассуждения могут идти на английском/китайском — это нормально, но финальный `content`
  без якоря может смешивать языки.
- Показывай пользователю только `content`, `reasoning_content` — никогда.
- Формат чисел в ответах клиентам: «15 191 ₽», не «15191.0».

## 7. Надёжность

- `max_tokens` — явно в каждом запросе (в thinking помни: это ещё и бюджет рассуждений).
- Ретраи: на 5xx и пустой `content` — до 3 попыток с паузами 2/4/8 с.
- Стриминг (`stream=True`) для всего, что видит человек, — V4 с thinking иначе кажется зависшим.
- Логируй `usage` каждого ответа (токены вход/кэш/выход) — так увидим реальную цену навыка.
- Жёстких rate-limit у DeepSeek нет, но под нагрузкой ответы замедляются — ставь таймаут ≥ 120 с
  для thinking-запросов.

## 8. Карта навыков → конфигурация

| Навык | Модель | Thinking | temp | Особенности |
|---|---|---|---|---|
| Ответы клиентам в мессенджере | flash | выкл | 1.3 | стриминг; стоп-темы → человеку |
| Извлечение заявки → CRM | flash | выкл | 0.0 | JSON mode + валидация схемы |
| КП и документы | flash | выкл | 1.3 | шаблон в кэшируемой части |
| Telegram-бот: расчёт по прайсу | flash | выкл | 0.0 | цена только из get_price |
| Описания товаров (Excel) | flash | выкл | 1.5 | батчами; критично кэшировать инструкцию |
| Сложный разбор / планирование | pro | вкл | — | reasoning_content passthrough! |

## 8а. Методики промптинга (проверено по GitHub DeepSeek и документации)

1. **Инструкции — в user, не в system.** В thinking-режиме перегруженный system prompt —
   главная причина игнорирования команд. System держи коротким (язык, роль, запреты),
   всю конкретику задачи — в сообщение пользователя.
2. **Zero-shot вместо few-shot** для thinking-режима: примеры-демонстрации ухудшают
   качество рассуждающих моделей (на 5–8 п.п. при штатных температурах). Исключение —
   исправление повторяющейся ошибки парой «Неправильно: … / Правильно: …»: негативный
   пример работает надёжнее, чем «не делай так».
3. **«Думай пошагово» — только для flash без thinking.** Thinking-модель уже рассуждает,
   просьба «think step by step» добавляет шум. Для расчётов с точным ответом проси:
   «финальный ответ помести в \boxed{}» — легко парсить.
4. **Жёсткая разметка:** инструкции сверху, вопрос снизу, входные данные в явных
   ограничителях (```…``` или <текст>…</текст>). V4 чувствителен к структурным маркерам;
   это же — базовая защита от промпт-инъекций в клиентском боте.
5. **Pro требует структуры:** v4-flash сильнее на прямых ответах; v4-pro раскрывается,
   когда рассуждение структурировано в промпте («сначала проанализируй X → сравни с Y →
   выведи Z»). Pro без структуры — переплата без выигрыша.
6. **Агентские оболочки бери из официального каталога**
   [awesome-deepseek-agent](https://github.com/deepseek-ai/awesome-deepseek-agent):
   24 проверенных инструмента с конфигами. Оболочки Claude-семейства подключай через
   Anthropic-эндпоинт `https://api.deepseek.com/anthropic` — он сам возит thinking-блоки,
   и правило про reasoning_content (раздел 2, п. 2) исполняется автоматически.

## 9. Чек-лист самонастройки (выполни по порядку)

1. Замени ID моделей: `deepseek-chat` → `deepseek-v4-flash`, `deepseek-reasoner` →
   `deepseek-v4-flash` + thinking (или `deepseek-v4-pro` для сложного).
2. Проверь base_url: `https://api.deepseek.com` (или `/anthropic` для Anthropic-протокола).
3. Для каждой задачи из раздела 8 выставь thinking и температуру по карте.
4. В обработчик истории добавь сохранение `reasoning_content` в assistant-сообщениях
   (для thinking-веток с инструментами).
5. Убери отовсюду `tool_choice="required"` и адресный tool_choice → `"auto"` + ретрай-валидация.
6. Structured output переведи на JSON mode + схему в промпте + валидатор.
7. Перестрой промпты под кэш: статика в начало, динамика в конец (раздел 5).
8. Первой строкой системного промпта: «Отвечай только на русском языке».
9. Включи логирование `usage` и ретраи по разделу 7.
10. Доложи, что изменил, и переходи к тестам.

## 10. Тест-план (прогоним вместе сразу после настройки)

| # | Тест | Ожидаемо |
|---|---|---|
| 1 | Пинг: «Ответь одним словом: работаю» на flash без thinking | «Работаю», < 3 с |
| 2 | Русский: вопрос про уход за сеткой | ответ целиком на русском |
| 3 | JSON: заявка «Хочу перегородку 1600 на 2200, я Иван, +7...» → схема {имя, телефон, товар, размер} | валидный JSON, temp 0.0 |
| 4 | Tool call: «сколько стоит перегородка 1600x2200?» с get_price | вызов инструмента, в ответе **15 191 ₽** (из прайса, не от модели) |
| 5 | Multi-turn thinking + инструмент (pro): два хода после tool call | нет 400 про reasoning_content |
| 6 | tool_choice="required" (негативный) | 400 — подтверждаем, что в коде его нет |
| 7 | Кэш: один и тот же системный промпт дважды | во втором `usage` виден cache hit |
| 8 | Описание товара (temp 1.5): «сетка 1000x1500» | живой текст без выдуманных цен |
